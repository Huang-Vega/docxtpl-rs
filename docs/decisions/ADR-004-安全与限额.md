# ADR-004：资源限额、安全与错误政策

- 状态：已接受（P0；P1 数值校准见 docs/security-limits.md）
- 决策日期：2026-09-24

## 决策

1. 上游对 ZIP/XML 输入**没有任何限额**；限额是本项目的安全增强，属于对上游的
   documented-deviation（安全侧），corpus 全部在限额内，不影响差分。
2. 默认限额（`docxtpl-opc::PackageLimits`，P1 校准后数值）：
   - `max_entries` = 1 000（ZIP 条目数）
   - `max_entry_uncompressed` = 32 MiB（单条目解压后大小）
   - `max_total_uncompressed` = 128 MiB（总解压大小）
   - `max_compression_ratio` = 200（压缩比，拦截 zip bomb）
   - `max_output_size` = 128 MiB（写出包大小）
   - XML 嵌套深度 ≤ 512（docxtpl-xml 解析器）
3. URI 校验：拒绝绝对路径、`..` 父目录逃逸、反斜杠、驱动器号；重复项按
   精确、大小写折叠、百分号解码折叠三种口径检测，冲突即报错。
4. 错误政策：可预期失败一律 `Result`，禁止 unwrap/expect/panic；错误分层
   （Input/Zip → OPC → XML → Template → Context → Limit → Output），保留来源并带 part 与位置。
   公开错误类别保持稳定，具体文本可演进。
5. 禁用外部实体（DTD/XXE）；宽松(recover)解析仅用于渲染结果愈合，且所有愈合动作记录诊断。

## 复核

- P1 corpus 的样本、实测最大值和局限记录在 security-limits.md；扩大真实模板集时复核。
- 高危安全问题触发发布冻结（代码规范 §6）。
