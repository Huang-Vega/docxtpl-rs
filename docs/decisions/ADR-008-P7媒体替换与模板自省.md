# ADR-008：P7 媒体/嵌入替换族与模板自省（replace_media / replace_pic / replace_embedded / replace_zipname / reset_replacements / get_undeclared_template_variables）

日期：2026-09-26
状态：已接受
阶段：P7a（媒体替换族 + 未声明变量自省）

## 背景

P4–P6 解决"渲染时注入新内容"。上游 docxtpl 另有一族在保存时
**替换既有二进制 part** 的 API（`template.py` L749-878），以及一个
不渲染、只做模板静态自省的辅助函数（L894-927）：

- `replace_media(src_file, dst_file)`：以源文件字节的 CRC32 注册，
  保存后把包内 `word/media/` 下 CRC 相同的条目内容换成目标字节；
- `replace_embedded(src_file, dst_file)`：同上，作用于
  `word/embeddings/`；
- `replace_zipname(zipname, dst_file)`：按 zip 条目全名精确替换
  任意 part；
- `replace_pic(embedded_file, dst_file)`：pre-processing 阶段按
  DrawingML 图片的 cNvPr name/title/descr 标识定位并就地替换
  target part 的 blob；
- `reset_replacements()`：清空上述四类注册；
- `get_undeclared_template_variables(context=None, jinja_env=None)`：
  对 body 与全部 header/footer 做 patch_xml 后用裸 jinja 环境做
  未声明变量元分析。

本 ADR 记录 P7a 的移植决策。上游 `docx`（富文本图片插入）等更大
范围的搭车特性不在 P7a 内。

## 探针钉死的上游事实（docxtpl 0.20.2 + python-docx 1.2.0）

1. **字节替换发生在 save 之后重开 zip**（post_processing，
   template.py L749-786）：逐条目判定，优先级
   `filename in zipname_to_replace`（精确全名，前导 `/` 先
   strip）>`startswith("word/media/") and CRC in crc_to_new_media`
   >`startswith("word/embeddings/") and CRC in crc_to_new_embedded`；
   CRC = `binascii.crc32(buf) & 0xFFFFFFFF`（与
   `crc32fast::hash` 同算法同结果）。只换 blob：part 名、
   `[Content_Types].xml`、rels、`wp:extent` 尺寸全部不动。
   页眉引用的图片因 media part 全局唯一而一并命中。
2. **replace_pic 在 pre_processing**（_replace_pics，L793-878）：
   扫主 document part，再按主 rels 中 HEADER/FOOTER 关系
   **出现序**（不去重、先 header 后 footer）扫各目标 part。
   每 part 取 `//a:graphic/a:graphicData`，仅处理
   `@uri == nsmap["pic"]` 的图片形态；从
   `pic:blipFill/a:blip/@r:embed` 取关系 id（无则 continue）、
   `pic:nvPicPr/pic:cNvPr` 取 `@name`（缺失时 xpath[0] 抛
   IndexError，被 per-graphicData 的 `except Exception` 整体
   吞掉），`@title`/`@descr` 缺省为空串。
3. **标识匹配按 dict 注册插入序、命中即 break**：每个
   graphicData 依次试全部已注册 img_id，与 name/title/descr
   任一相等即替换 `doc_part.rels[rId].target_part._blob`
   （同一 part 被多处引用时只一份 blob，全部引用同时生效）。
   先注册的 key 会遮蔽同图上的后注册 key（p7_pic_match 实证：
   两图默认 name 均为 python-docx 固定的基础名 `"image.png"`，
   第二张必须改名，title key 才可能独立命中）。
4. **allow_missing_pics 默认 False**：全部 part 扫完后，任一
   注册标识未命中即 `ValueError("Picture %s not found in the
   docx template")`。
5. **不渲染直接保存**（L887-888 路径）：重新
   `Document(template_file)`，不跑 fix_tables/fix_docpr_ids，
   body docPr id 保持模板原值（渲染路径会被重排为 1001 起）；
   pre/post 替换处理照常执行。
6. **get_undeclared_template_variables**：新 Document，
   `patch_xml(xml_to_string(body))`，再两遍主 rels
   （HEADER_URI、FOOTER_URI）对 blob 非空目标 append
   `patch_xml(xml_to_string(parse_xml(blob)))`；裸
   `Environment().parse` + `meta.find_undeclared_variables`。
   实证 `{{a}}{%if b%}{{c}}{%endif%}` 与
   `{%p for item in items%}{{item.name}}{%p endfor%}` 合取结果为
   `{a,b,c,items}`——循环变量 item 由 jinja 元分析自动排除，
   `items` 保留。可选 `context` 差集参数与自定义 `jinja_env`
   不移植（DEV-0013）。
7. **embeddings 挂载**：`Part(PackURI("/word/embeddings/x.bin"),
   content_type, blob, package)` + `doc.part.relate_to(part,
   RT.oleObject)` 后，python-docx 保存保留 part 与 CT Override，
   无需手工改 `[Content_Types].xml`。

## 决策

1. **错误分类**：`TemplateErrorKind::InvalidArgument` →
   `oracle_exception()` 映射 `"ValueError"`（对齐 replace_pic
   缺失标识；上游其余替换 API 不做存在性校验，CRC/zipname
   未命中静默无操作）。
2. **新模块 `docxtpl-rs/src/replacements.rs`**：`Replacements`
   持四张注册表——media/embedded 为 `HashMap<u32, Vec<u8>>`
   （key=源字节 CRC32）、zipnames 为 `HashMap<String, Vec<u8>>`、
   pics 为 **`Vec<(String, PicReplacement)>` 保序**（决策 3）。
   `reset()` 对齐 reset_replacements 清空全部四类。
3. **pics 保序 Vec 而非 map**：上游 `pics_to_replace` 是 dict，
   匹配按插入序且命中即 break，missing 报错也按插入序；重复
   注册同一标识按 dict 赋值语义覆盖字节并保留首次注册位置。
4. **两段落盘点**：
   - `apply_pic_replacements`（pre 路径，渲染/不渲染均执行）：
     复用 docxtpl-xml 的 `parse_strict`/xpath 等价手工遍历
     （`descendants` 含自身需 skip 根、无命名空间属性传 `""`），
     per-graphicData 任何结构缺失整体跳过（对齐上游吞异常）；
     header/footer 目标按主 rels 出现序、不去重枚举（模块内
     独立的 `header_footer_targets`，与 lib.rs 渲染用去重版
     `story_parts` 区分）。blob 非 UTF-8 返回带 part 名的
     `NotUtf8` 错误（良构 docx 的 document/header/footer 必为
     UTF-8 XML，正常不可达）。
   - `apply_byte_replacements`（post 路径）：zipname 精确（前导
     `/` strip）>`word/media/`+CRC>`word/embeddings/`+CRC`，
     只改 part 字节，part 名/CT/rels 不动。
5. **会话编排**：`RenderSession` 新增 `replacements` 字段与五个
   链式方法（`replace_media`/`replace_embedded`/`replace_zipname`
   /`replace_pic`/`reset_replacements`，均收 `impl AsRef<[u8]>`
   与 `&str`，返回 `&mut Self`）；`finish()` 末尾执行
   pic 替换 → CT 归一 → 字节替换 → OPC 校验；新增
   `finish_without_render()` 对齐不渲染直接保存（不跑
   fix_tables/fix_docpr_ids，docPr id 保持模板原值）。
6. **模板自省**（docxtpl-template）：
   `render::find_undeclared_variables(doc_xml, story_xmls)`
   对 body 子树与各 story 根元素分别 patch 后拼接，用 minijinja
   `template.undeclared_variables(false)` 收集，返回
   `BTreeSet<String>`（排序稳定，等价 Python sorted）。
   `DocxTemplate::undeclared_variables()` 复用渲染侧 story_parts
   枚举（去重版）。自省解析树根节点即顶层元素（无虚拟 Document
   层），严格解析失败按 XML 错误上报。
7. **fixture**：新增 7 个 `p7_*`（media_body/media_header/
   pic_match/pic_missing/embedded_zipname/replace_only/
   undeclared_vars），全部 context_kind="python"；
   `p7_replace_only` 标记 `skip_render: true`，runner 对应跳过
   `tpl.render(context)` 但仍 `tpl.save`；素材 8 个固定字节文件
   入 `tests/fixtures/media/`（PNG 为确定性手工构造，embed 为
   固定 ASCII）。不得改 fixture/golden 放宽断言。

## 影响

- 新公开 API：`RenderSession::replace_media` /
  `replace_embedded` / `replace_zipname` / `replace_pic` /
  `reset_replacements` / `finish_without_render`；
  `DocxTemplate::undeclared_variables`；
  `docxtpl_template::find_undeclared_variables`。
- 新依赖：`crc32fast = "1.5"`（与 Python binascii.crc32 同
  IEEE 多项式，逐 fixture 差分钉死）。
- 验收：85 个 render fixture 全部与 Python oracle 一致（81 逐
  part 字节匹配 + 4 错误类别：Syntax×2、Image×1、Value×1），
  7 个 p7 全 MATCH（含 skip_render 不渲染路径）；golden 计数
  85（full_patched）/83（pre_recover）。
- 已知限制：DEV-0013（compatibility.md §5）。
