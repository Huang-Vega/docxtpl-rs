# ADR-001: Pinned Upstream Baseline and License Obligations

- Status: Accepted (P0)
- Decision date: 2026-09-24

## Context

The project aims at a "semantics-preserving port". A single upstream reference implementation must be pinned; otherwise equivalence claims have no basis.

## Decision

1. The baseline is pinned to **docxtpl 0.20.2**:
   - PyPI sdist: `docxtpl==0.20.2` (released 2025-11-13, i.e. the latest version at the time).
   - Git tag `v0.20.2`, commit SHA `cf5437bdf5d30f9362149ddea508d6d9f008b6cd`.
   - The upstream source is fetched into `third_party/` via `pip download --no-binary :all:` (this directory is not checked in; see `.gitignore`).
2. Python-side dependencies (jinja2, python-docx, lxml) are pinned exactly in `tests/oracle/requirements.txt`; the oracle report records the full version fingerprints.
3. The upstream declared license is **LGPL-2.1-only**. Because this port transcribes the upstream regular expressions and algorithm structures item by item during the patch step, it is fairly likely to constitute a derivative work. The workspace therefore uniformly declares `LGPL-2.1-or-later`, and no upstream source code is copied into the repository.
4. Before the P8 1.0.0 release, a review is required: confirm the derivative-work boundary (regexes/algorithms vs. literal code) and reassess the license declaration. Apart from the 16 docxtpl 0.20.2 LGPL-2.1 test templates registered in ADR-009, fixtures are generated by this project; the upstream templates are stored with the repository, with their exact provenance and license attribution preserved in the manifest.

## Consequences

- Upgrading the baseline is a standalone milestone and must be accompanied by a full diff report.
- Upstream evidence cited by any behavioral PR must point to this pinned version.
